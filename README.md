# Text Studio

A single Next.js app with integrated, in-browser image-to-text OCR.

## Text Studio: integrated image-to-text OCR

The root app is the OCR workspace; it is not a separate project or service.
Select or drop a PNG, JPG, WebP, or BMP (up to 12 MB), then choose **Extract
text**. English text can be edited, copied, or downloaded as a `.txt` file.
**Use sample** loads a bundled test image; it still runs real OCR.
PDF input and additional languages are not implemented.

Recognition uses Tesseract.js in a browser Web Worker. Images and extracted
text are not sent to an OCR server or saved by the app. Existing Vercel
Analytics and Speed Insights remain enabled for page/performance telemetry.
No OCR API keys, environment variables, or standalone `tesseract-ocr` project
are needed. The separate project's Windows executables are not used.

`npm ci` installs the locked engine and English language package. `npm run
dev` and `npm run build` prepare the worker, all supported WASM variants,
and language data under generated `public/ocr/`, served by this same app.
There are no CDN dependencies at recognition time. Turborepo caches these
assets with the build. Do not commit generated `public/ocr/` files.

## Getting Started

```sh
npm ci
npm run dev
```

Open http://localhost:3000. For a production check, run `npm run check`, then
`npm start`. To smoke-test the full OCR flow, choose **Use sample**, choose
**Extract text**, and verify the result includes “A little less typing.” and
“Everything runs in your browser.” Edit a line, then test **Copy text** and
**Download .txt**. Also check a personal image and an unsupported file;
unsupported inputs should show a useful error without starting OCR.

## Vercel deployment and telemetry

This Next.js app lives at the repository root. In Vercel, use the **Next.js**
framework preset, leave **Root Directory** empty, and leave build, output,
install, and development command overrides disabled.

The root layout mounts Web Analytics and Speed Insights once for all routes.
Enable those products on the Vercel project and deploy to serve their scripts
and collection endpoints. Dashboard metrics require real visits; a successful
build alone does not prove events have been received.

Open a pull request to verify a Preview deployment before merging to `main`.
Keep Preview environment variables separate from Production credentials.

Run all checks with `npm run check`. Turborepo 2.11.11 runs lint and the
production build, then typechecks against the route types generated by the
build. The individual commands remain available as `npm run lint`,
`npm run typecheck` (after a build), and `npm run build`.

### Vercel CI setup

`turbo.json` tags `lint`, `build`, and `typecheck` with `ci` and caches Next.js
build outputs while excluding its internal cache and development outputs.
The repository declares npm 11.20.0 in `packageManager` for reproducible task
and lockfile discovery. Run `npm ci` before `npm run check`.

Vercel CI is **not enabled by this configuration alone**. It currently does
not support public repositories. If this repository becomes eligible, a
maintainer can run the following from a local clone before pushing a branch
containing these tasks:

```sh
vercel ci enable --remote origin --scope alexablissislove-9788
```

The dashboard task analysis reads the default branch, so merge this setup
before analyzing it there. Verify the first remote run and its tasks before
making Vercel CI a required merge check. See the
[Vercel CI prerequisites and limitations](https://vercel.com/docs/ci).

The scoped npm override for `@typescript-eslint/typescript-estree` selects
`minimatch` 11.0.8 to address GHSA-g3hv-75wg-m249. It leaves legacy minimatch
consumers unchanged. Remove the override once TypeScript ESLint declares a
patched dependency; recheck lint and project-service glob matching when updating it.
